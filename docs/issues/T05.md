## Problema

Implementar campo de pesquisa que atualiza ProductQuery no AppScope.

## Entrega de código

Implementar o módulo Flutter `lib/features/catalog/catalog_feature.dart`. Não basta alterar texto, documentação ou devolver dados fixos. Quem implementa serviço/helper deve demonstrar entrada/resultado/erro no módulo conectado à Oficina.

## Critérios de aceite

- Busca no catálogo importado; permite limpar; mantém marca/categoria selecionadas.
- Estado vazio/erro tratado quando aplicável.
- Teste manual descrito no PR; lógica de parsing, agregação e moderação com teste automatizado.
- `flutter analyze` e `flutter test` passam; PR revisado por um colega.

## Contratos e arquivos

- Pasta principal: `lib/features/catalog/`.
- Arquivos adicionais: nenhum obrigatório; testar na própria pasta de testes.
- Usar scope.setQuery; a listagem base já reage. Submit explícito evita requisição a cada tecla.
- Ler [contratos](https://github.com/ADSSTech/na_lata/blob/main/docs/CONTRATOS.md).
- Não editar core/registro de rotas nem dependências sem coordenar com o professor.

## Dependências

Nenhuma; T02 no modo real. Desenvolver com fake/fixture enquanto a dependência não foi integrada. Módulos recebem `FeatureContext`; produto pode ser null na Oficina. Usar a ficha do catálogo para cenários de produto.

## Roteiro de teste

Executar os critérios acima com um exemplo válido e um inválido/vazio. Registrar aparelho, modo demo/Supabase e evidência no PR. Validar integração real quando dependências estiverem disponíveis.

## Fluxo de trabalho

Assuma a issue → branch `feat/NUMERO-descricao` → código → commit → PR com `Closes #NUMERO` → revisão de colega → ajustes → merge coordenado.

Identificador pedagógico: **T05**. Use o número real do GitHub no nome da branch e no PR.
